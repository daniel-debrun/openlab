Openlab

A research control plane: the plan is fixed before the first run, every trial is counted, the data a model sees is only what was known at the time, the holdout is a person's signed act, and every number is computed from a hash-chained record. Agents (Claude Code, Codex) do the work; a person supervises. Map as of 2026-10-11, branch research-framework.

Overview

Three ways in, one core. Every action is a tool behind one dispatch, so the CLI, the web app, the MCP server (what an agent calls) and the hooks all enforce the same rules.

1. Paper to verified code openlab replicate

An agent drafts a replication plan from the paper (methods, claims quoted on their pages, metric, tolerance), a person approves it signed, a builder agent rebuilds it in a sandbox, and openlab computes each verdict.

2. Research from a prompt openlab propose

A paragraph becomes a proposal: hypotheses with falsifiers, branches with budgets, stop rules and kill criteria. A person approves it; a lead agent runs it as a tree of agents.

3. A literature review openlab study (review)

A sealed protocol: discovery across OpenAlex/arXiv/Crossref, screening, evidence quoted from full text and checked on its page, a PRISMA flow, contradiction searches.

Supervising agents openlab watch / inbox

Spawned agents run under a supervisor with $ / minute / turn budgets; hooks see every tool call; a person pauses, directs (agent tell), and decides inbox requests with a passphrase-protected key.

How a verdict is computed

  • Fidelity: |ours - paper| <= tolerance (the target's, or up to max with a justification).
  • Replication: our interval vs the paper's value and the reference (the best gating baseline). Improvement claims keep the side of the reference; a method that trails its baseline is a level (fixed this session).
  • Several runs (seeds, datasets): the mean; seeds add t * sd / sqrt(n) to the interval.
  • Inconclusive while any gating fidelity fails: a bad rebuild cannot fail the paper.

What the person signs

  • The plan (sha); a changed plan is approved again, keeping the primary method and the fixed fields.
  • A person-amended metrics.py counts as approved (no second approval).
  • Inbox requests: amendments (with the fields they set), holdout looks, budgets.

What hooks refuse

  • Writes into .openlab/, the vault, the person key, openlab.toml.
  • Person acts from an agent (holdout looks, protected amendments), in any wrapper.
  • Edits to sealed study.toml without an amendment; native sub-agents when disallowed.

What watch flags

  • States: working, idle, waiting, stuck, paused, done / failed / lost.
  • RUN (a study run in progress, with progress), LOOP (the same refusal repeated), over budget, waiting on the inbox, bypass attempts.

Stepping away

  • [agents] notify in openlab.toml runs on a request and on an agent's end.
  • openlab inbox wait blocks until something needs the person.
  • Approving an ended requester's item resumes its work (--no-resume declines).

The record

.openlab/record.db: append-only SQLite; each node is hashed over its body, its links and its actor, chained to the previous head. Person nodes carry an Ed25519 signature. openlab study verify recomputes the chain and every signature against the workspace pin.

GroupNode kinds (38)
Plan and dataplan amendment dataset proposal person_key action agent
Runstrial run result model look reproduction forecast outcome
Organising the researchquestion hypothesis claim test assumption break dead_end approval
Literaturequery source document screen evidence comparison contra_search coverage recall retraction watch
Replication and papertarget fidelity replication paper

Computed fields (verdicts, intervals, "selected from N trials") are recomputed by the schema when a node is written; a typed value that disagrees is refused.

Guarantees and what enforces them

GuaranteeMechanism
The plan comes firstThe first run seals study.toml; later edits stop the next run until amended; protected fields (split, budget, sandbox, audit, primary metric, known_at, metrics, ...) need a signed person amendment.
Features cannot see the futureViews hold only rows with known_at <= t; the truncation audit replays sampled steps in fresh processes holding only the past; a claim cannot rest on an unclean audit.
Research never loads holdout rowsThe runner stages research rows only; static holdout labels live in the vault outside the study; the sandbox masks .openlab/ and data/.
Every trial is countedA run's key hashes code, data, spec and packages; identical keys are cached and free; past the budget a run is refused; a study on the same data continues its count or a person declares it fresh.
Only a person looks at the holdoutA look is a signed person node bound to the hashes; hooks refuse an agent's attempt in any wrapper.
Numbers are computed, not typedVerdicts, levels, intervals and selection notes are derived from what they rest on.
Evidence is where it saysA quote must be on its page and contain its numbers; table claims must sit under their column header (multi-level headers aligned by position).
The paper says what the record saysThe paper build refuses unbound numbers, "significant" without a rejecting test, stale bindings, and equations that disagree with their functions.
The record is not quietly editedAppend-only, hash-chained, signed person acts, workspace pin; verify recomputes it all. Tamper-evident, not tamper-proof.

Modules and inner workings

openlab/study: definition

  • spec: load and validate study.toml; seal into the record; amend with a recorded diff.
  • data: registered datasets, materialised to parquet, recorded with sha and card.
  • view: point-in-time views (known_at, vintages).
  • splits: decisions per segment, refit cadence, folds, holdout carve, reseeding.
  • durations, clock: "18h", "1d", calendar months; timestamps read one way.
  • fingerprint: spec, code files, data and environment hashes; the run key.

openlab/study: execution

  • runner: temporal walk (refit / update, wide-distribution reducer, progress), static folds, truncation audit with memory gating, evaluation, groups, policy.
  • sandbox + child: the job in a bwrap child; the only place study code runs.
  • baselines: persistence, climatology, majority, ..., and model:Name classes.
  • registry: MLflow model store; determinism check of the packed model.
  • reproduce: re-run a recorded run from the record alone; signing, bundles.
  • branches: per-branch copies of model.py for parallel experimenters.

openlab/study: scoring

  • metrics: versioned registry (mae, rmse, crps, crps_empirical, brier, logloss, auc, coverage, pinball, ...); per-row statistics for the bootstrap; a study's own metrics adopted in the sandbox.
  • inference: bootstrap / block bootstrap intervals, paired differences, Diebold-Mariano, Holm.
  • variants: one result against another on the rows both scored.

openlab/study: the record

  • record: append-only hash-chained SQLite + content store.
  • schema: typed bodies per node kind, allowed links, computed fields; fidelity and replication fields; column checks for table quotes.
  • ledger: trial and holdout budgets per question and data, shared across studies.
  • vault: holdout labels outside the study; holdout: a person's look.
  • personkey: signatures on person nodes; show, graph: read views.

openlab/study: research flows

  • paperplan (+ cli): replicate: draft, lint, approve, build, status, report.
  • replication: the study behind a replication; fidelity / replication rows.
  • proposal (+ propose_cli): research from a prompt.
  • literature + evidence: discovery, screening, full text by page, quotes, comparisons.
  • claims, frontier: question tree, alpha-investing error budget, assumptions; what to do next.
  • forward, schedule, monitor, notify, checks: signed forecasts, cron, watches, alerts, SQL gates.
  • paper/: build, bindings, sections, lint: the paper from the record.

openlab/agents

  • store: control.db (agents, events, inbox, leases, directions, notify).
  • spawn + supervisor: start an agent's CLI, enforce $ / minutes / turns, pause, stop.
  • hooks (+ hook): PreToolUse / PostToolUse rules, bypass refusals, signed directions.
  • identity: attribution of every write; person: the key, pins, signed directions.
  • inbox: request kinds, describe, decide, resume; view + cli: agents, watch.
  • pricing, claude_setup: cost estimates; init for Claude Code / Codex.

openlab/app, sources, engine

  • app.registry: @tool registration and dispatch; server: web UI; study_tools, agent_tools, propose_tools, papers, tools, usage.
  • mcp_server: the tools over MCP, with a "openlab code changed" hint.
  • sources: one rate-limited, cached HTTP path; papers (OpenAlex, arXiv, Crossref), FRED / IMF / World Bank, BLS, BEA, Census, EIA, EPA, FDIC, NOAA, Treasury, USAspending, USDA, GDELT, Wikipedia; snapshots.
  • engine: the equation language (parse, semantics, units, proofs) behind derived claims and the equation gate (each paper equation bound to its function and checked on probe inputs).
  • envcli, doctor, init, thin_cli.
